# Rough Wireframes — LearnKK (사내 멘토링 통합 플랫폼 파일럿)

> Ideation · rough-mockups 단계 산출물 · 저충실도(러프) · 리드 design (서포트: product)
> 상위 입력: `intent-capture/intent-statement.md`, `scope-definition/scope-document.md`, `scope-definition/intent-backlog.md`
> 근거: rough-mockups-questions.md (Q1=반응형 상단탭, Q2=내 코호트 대시보드 첫 화면, Q3=반응형)

## 내비게이션 원칙 (Navigation)

- **반응형**: 데스크톱은 **상단 탭 바**, 모바일은 **하단 탭 바**로 전환(Q1·Q3).
- 공통 탭: `홈(내 코호트)` · `코호트 탐색` · `알림/공지` · `내 정보`. 관리자에게는 `관리자` 탭 추가.
- 저충실도이므로 색/타이포는 refined-mockups에서 확정.

## 화면 4 — 코호트 상세 (B-M3 / B-M4)

```
+------------------------------------------+
|  파이썬 스터디 3기               (멘토: 홍길동) |
|  [ 공지 ] [ 진도·출석 ] [ 멤버 ] [ 보고서 ]     |
|------------------------------------------|
|  공지 탭: 최신 공지 + 외부 미팅 링크        |
|  진도·출석 탭:                             |
|    회차별 목록 | 출석 상태(인증/미인증)     |
|    (멘토) [ 파일 첨부 업로드 ] → 출석 인증   |
|      · 첨부: 이미지/문서 파일 1개 이상       |
|  멤버 탭: 참여자 목록                       |
|  보고서 탭: [ 최종 보고서 제출 ] → 화면 4b  |
+------------------------------------------+
```
증빙 업로드는 **파일 첨부(이미지/문서)** 방식이다(텍스트 메모 입력이 아님). 첨부 즉시 해당 회차 출석이 인증 처리된다.

## 화면 6 — 관리자 (B-M2 승인 / B-M8 지표·이력)

```
+------------------------------------------+
|  관리자                                    |
|  [ 대기 승인 ] [ 운영 지표 ] [ 증빙이력 ] [ 보고서이력 ] |
|------------------------------------------|
|  대기 승인: 정원 마감 코호트의 대기 신청 목록 |
|            각 항목 [ 승인 ] / [ 거절 ]      |
|  운영 지표: 완주 코스 수 / 출석·수료율 /    |
|            증서 발급 수                      |
|  증빙이력: 회차별 출석 증빙(파일) 목록 조회   |
|  보고서이력: 코호트별 최종 보고서 제출 목록   |
+------------------------------------------+
```
증빙 이력과 최종 보고서 이력은 **서로 다른 하위 뷰**로 분리한다(B-M8 세부 기능 구분).

## 화면 7 — 수료 결과 (B-M6)

```
+------------------------------------------+
|  수료 완료!                                |
|  [ 수료증 이미지 미리보기 ]  ( 다운로드 )   |
|  정산 상태: "정산 조건 충족" ✅  (메시지)   |
+------------------------------------------+
```

**수료 조건(placeholder, requirements에서 확정):** 러프 단계 가정으로
"인증된 출석 회차 ≥ 전체 회차의 일정 비율(예: 80%) + 최종 보고서 제출 완료" 를 둔다.
정확한 임계값과 "정산 조건"의 정의는 requirements 단계에서 확정한다(scope-document 오픈 이슈와 연결).
미충족 시 화면 7은 "미수료 — 부족 항목 안내"로 대체된다.

## 접근성 메모 (Accessibility, 러프 수준)

- 폼 라벨·버튼에 명확한 텍스트 레이블, 키보드 포커스 순서 고려.
- 상태(모집중/마감, 인증/미인증)는 색상만이 아니라 텍스트로도 표기.
- 세부 WCAG 점검은 refined-mockups/build 단계에서 수행(완전 준수는 보조기술 수동 검증 필요).
