## 팀 개요 (Team Profile)

- **규모**: 4~6명 (Q1=C)
- **역할**: 전원 **풀스택** (React 프론트 + Spring 백엔드 모두 소화, Q2=B)
- **숙련도**: React·Spring **둘 다 능숙** (Q3=A)
- **투입**: **풀타임 집중** (Q4=A)

## 역량 대 백로그 (Capacity vs Backlog)

`intent-backlog.md`의 Must 8개(코호트·참여·출석·공지·인증·증서·보고서·지표)는 표준 CRUD 중심 웹 기능으로,
React+Spring 풀스택 4~6명 풀타임이면 **충분히 감당 가능**. `feasibility-assessment.md`의 GO 판정과 정합.

- 첫 슬라이스(코호트 개설 → 선착순 참여)는 소수 인원으로 빠르게 착수 가능.
- 병렬화 여지: Must 기능이 도메인별로 분리 가능(코호트/참여, 출석/증빙, 지표/보고서) → 2개 작업 축으로 나눌 수 있음.

## 준비도 & 갭 (Readiness & Gaps)

| 항목 | 상태 | 비고 |
|---|---|---|
| 기술 역량 | 강함 | React·Spring 능숙, 스택 학습 부담 없음 |
| 투입도 | 강함 | 풀타임 |
| 기획/PM | 보통 | 별도 기획 인원 없음 → 풀스택이 겸함(product 산출물이 보완) |
| **디자인/UX** | **갭** | 별도 디자이너 없음(Q2=B) → rough-mockups/refined-mockups 단계와 경량 디자인으로 보완 |

## 종합 (Overall)

- 파일럿 실행에 **적합한 팀 구성**. 기술 리스크 낮음.
- 유일한 갭은 전담 디자인/UX 부재이며, 후속 목업 단계와 단순한 UI(증서=이미지 1장 수준 등)로 완화 가능.
