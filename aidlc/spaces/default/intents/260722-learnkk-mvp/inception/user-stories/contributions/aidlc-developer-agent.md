## Contribution

구현 관점(INVEST·Bolt 슬라이싱·숨은 복잡도)으로 리드 초안을 검토했다. 커버리지 매핑은 FR-1~11을 빠짐없이 담아 견고하다. 다만 엔지니어링이 착수하려면 채워야 할 선행 스토리가 몇 개 비어 있고, 두 스토리는 한 Bolt 슬라이스로 보기엔 크다.

### 1. 역할 배정·관리자 부트스트랩 누락 (블로커)
US-1 회원가입은 "직원"만 생성한다. 그러나 멘토/멘티/관리자 3역할이 전 스토리의 전제인데, **직원이 어떻게 멘토가 되고 관리자가 부여되는지** 스토리가 없다. team.md의 DTO 경계·Spring Security 인증 전제상 RBAC은 첫 Bolt 이전에 확정돼야 한다.
- 멘토 vs 멘티는 별도 역할인가, 아니면 "코호트를 개설하면 멘토, 참여하면 멘티"라는 컨텍스트 역할인가? (구현 방식이 완전히 갈림)
- 최초 관리자 계정은 회원가입 경로로 만들 수 없다 → **시드/부트스트랩 경로**(데이터 시딩 또는 부여 스토리)가 필요하다.

### 2. 회차(세션) 구조의 생성·조회 명시 부족
project.md는 "회차 단위 구조"를 확정했다. US-3에서 회차 수만 입력받는데, 개설 시 **회차 레코드 N개 생성**과 회차 목록 조회가 US-9/US-10에 암묵적으로 녹아 있다. 회차가 1급 엔티티로 다뤄져야 US-9(회차별 증빙)·US-12(80% 판정)·US-13(전 회차 인증)이 성립한다. 회차 생성/상태 조회를 US-3 또는 US-10 수용 기준에 명시 권장.

### 3. 선착순 동시성 = 가장 큰 숨은 복잡도
US-6은 (a)여유 시 즉시 확정, (b)마감 시 대기 등록, (c)유니크 제약+비관적 락 동시성, (d)중복 방지를 한 스토리에 담고 있다. team.md가 지정한 `SELECT ... FOR UPDATE` + `ExecutorService`/`CountDownLatch` 동시성 테스트까지 포함하면 **한 Bolt 슬라이스로는 과대**하다. walking skeleton(Bolt 1: 개설→참여 1명→출석)은 (a)+(d)만 필요하다.

### 4. 수료/정산 판정 트리거 시점 미정
US-12(멘티 출석≥80%)와 US-13(멘토 전 회차 인증+보고서)은 서로 다른 기준이라 정의는 명확하나, **언제 판정하는지**가 빠졌다 — 코호트 종료 액션 시점? 실시간 재계산? 배치? 구현 방식(이벤트 vs 온디맨드 계산)이 이 결정에 종속된다.

### 5. 파일 스토리지·다운로드 접근 경로
US-9 증빙, US-11 보고서 첨부, US-12 수료증 이미지가 모두 파일을 다룬다. NFR-2가 로컬 서버(Docker)이므로 **저장 위치(로컬 FS 볼륨 vs DB blob)** 결정이 필요하고, US-15 관리자 이력 조회 시 파일 다운로드/열람 동작이 수용 기준에 없다.

## Positions

- **OBJECTION** — 역할 배정 및 최초 관리자 부트스트랩 스토리 누락. 3역할 RBAC 없이는 어떤 Bolt도 착수 불가. 최소한 "역할 모델 + 관리자 시드" 스토리(또는 US-1 확장)를 추가해야 한다.
- **RECOMMENDATION** — US-6을 두 스토리로 분할: (US-6a) 정원 여유 시 선착순 자동 확정 + 중복 방지, (US-6b) 정원 마감 시 대기 등록 + 동시성 경계(유니크 제약·비관적 락·동시성 테스트). 6a가 walking skeleton Bolt 1에 들어간다.
- **RECOMMENDATION** — 회차를 1급 엔티티로: US-3 수용 기준에 "개설 시 회차 N건 생성", US-10에 "회차 목록·상태 조회"를 명시.
- **RECOMMENDATION** — US-12/US-13 수용 기준에 판정 트리거 시점(예: 멘토 코호트 종료 액션 시 계산)을 명시.
- **RECOMMENDATION** — US-9/US-11/US-15에 파일 저장 방식과 다운로드/열람 접근을 명시. 파일럿 보안 보류(NFR-5)와 정합하되 저장 위치는 결정 필요.
- **RECOMMENDATION** — 멘토 자동 멤버십 명확화: 개설 멘토가 코호트 멤버로 자동 포함되는지(정산·보고서·공지 권한 판정에 영향).
