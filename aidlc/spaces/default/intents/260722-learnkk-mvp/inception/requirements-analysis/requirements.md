# Requirements — LearnKK (사내 멘토링 통합 플랫폼 파일럿)

> Inception · requirements-analysis 단계 산출물 · 리드 product
> 상위 입력: `ideation/intent-capture/intent-statement.md`, `ideation/scope-definition/scope-document.md`, `inception/practices-discovery/team-practices.md`
> 근거: requirements-analysis-questions.md (Q1~Q7)

## 개요 (Overview)

`intent-statement.md`의 목표(산발된 사내 멘토링 과정의 통합 관리)를 파일럿 기능 요구사항으로 구체화한다.
`scope-document.md`의 Must 8개(B-M1~B-M8)를 기능 요구(FR)로 전개하고, `team-practices.md`의 관행을 비기능 요구(NFR)로 반영한다.

## 사용자 역할 (Roles)

- **멘토(직원)**: 코호트 개설·수정, 회차/공지 관리, 출석 증빙 업로드, 최종 보고서 제출
- **멘티(직원)**: 코호트 탐색·선착순 참여, 진도·출석·공지 확인, 최종 보고서 제출, 수료증 수령
- **관리자(운영 담당 통합, Q5=A)**: 정원 마감 대기 승인/거절, 운영 지표·증빙 이력·보고서 이력 조회

## 기능 요구사항 (Functional Requirements)

### FR-1 회원가입·로그인 (B-M5)
- 이메일·성명·닉네임·비밀번호로 가입. 그 외 정보 미수집.
- 비밀번호는 BCrypt 해싱 저장(평문 금지).
- **수용 기준**: 유효 이메일 형식 검증; 중복 이메일 거부; 로그인 성공 시 내 코호트 대시보드로 이동.

### FR-2 코호트 개설·수정 (B-M1)
- 멘토가 제목·설명·**정원(capacity)**·기간·**회차(세션) 수**(Q6=A)를 지정해 개설/수정.
- **수용 기준**: 정원은 1 이상 정수; 회차 수 1 이상; 개설 즉시 "모집중" 상태.

### FR-3 코호트 탐색·선착순 참여 (B-M2, Q7=A)
- 멘티가 코호트를 탐색하고 참여 신청.
- 정원 여유 시 **선착순 자동 확정**. 정원 마감 시 **대기 신청**으로 등록되고 관리자 승인 시에만 확정.
- 동시성: 정원 초과 확정이 발생하지 않아야 함(DB 유니크 제약 + 비관적 락, team-practices).
- **수용 기준**: 정원 N에 동시 N+1 요청 시 정확히 N명만 확정; 초과분은 대기; 중복 참여 불가.

### FR-4 멘티 신청 상태·알림 (B-M2 후속)
- 멘티는 자신의 신청 상태(대기중/확정/거절)를 조회. 상태 변경 시 알림/공지에 통지.
- **수용 기준**: 관리자 승인·거절 결과가 멘티 상태에 즉시 반영.

### FR-5 회차별 출석 증빙 인증 (B-M3, Q4/Q6)
- 멘토가 회차별로 **증빙 파일 첨부 업로드**(이미지 jpg/png + 문서 pdf, 파일당 최대 10MB) → 해당 회차 출석 인증.
- 업로드된 증빙은 이력으로 보관.
- **수용 기준**: 허용 형식/크기 외 업로드 거부; 첨부 즉시 회차 출석 상태 "인증됨"; 증빙 이력 1건 적재.

### FR-6 코호트 공지 (B-M4)
- 멘토가 코호트 단위 공지 작성(외부 미팅 링크 공유 포함). 멘티가 조회.
- **수용 기준**: 공지 작성/조회 가능; 외부 링크 클릭 가능.

### FR-7 최종 보고서 제출 (B-M7, Q3=A)
- 멘토/멘티가 코호트 종료 시 **자유 서식 텍스트 + 선택적 파일 첨부**로 최종 보고서 제출.
- **수용 기준**: 제출 후 상태 "제출됨"; 관리자 보고서 이력에 표시.

### FR-8 수료 판정·수료증 발급 (B-M6, Q1=B)
- **수료 조건: 인증된 출석 회차 ≥ 전체 회차의 80%** (최종 보고서 제출과 무관).
- 수료 시 단순 **수료증 이미지 1장** 발급(다운로드).
- **수용 기준**: 출석 80% 이상 멘티에게 수료증 발급; 미달 시 "미수료 — 부족 항목 안내".

### FR-9 정산 조건 충족 메시지 (B-M6, Q2=A)
- 멘토가 코호트를 **정상 종료(모든 회차 출석 인증 완료 + 최종 보고서 제출)**하면 "정산 조건 충족" 메시지 표시.
- 실제 정산 처리·결제 없음(오프라인). 정산서는 메시지/기록 수준.
- **수용 기준**: 조건 충족 시 메시지 표시; 미충족 시 미표시.

### FR-10 관리자 기능 (B-M2 승인 / B-M8)
- 정원 마감 대기 신청 목록 조회 및 **승인/거절**.
- 운영 지표 조회, **증빙 이력**·**최종 보고서 이력** 각각 별도 뷰로 조회.
- **수용 기준**: 승인/거절이 멘티 상태에 반영; 증빙/보고서 이력이 분리 조회 가능.

### FR-11 운영 지표 (B-M8)
- 완주 코스 수 · 출석률/수료율 · 발급 증서 수 집계 표시.
- **수용 기준**: 지표가 실제 데이터와 일치.

## 비기능 요구사항 (Non-Functional Requirements)

- **NFR-1 플랫폼**: React(FE) + Spring(BE), FE/BE 분리 저장소(team-practices).
- **NFR-2 호스팅**: 초기 로컬 서버(Docker 컨테이너). 퍼블릭 클라우드 보류.
- **NFR-3 UI**: 반응형(데스크톱 상단탭 → 모바일 하단탭), 첫 화면 내 코호트 대시보드.
- **NFR-4 규모/성능**: 소규모 파일럿(<100명) 기준. 고성능/고가용 요구 낮음.
- **NFR-5 보안(파일럿)**: 비밀번호 BCrypt 해싱, 개인정보 최소 수집. 파일 업로드 검증·보안 스캔·TLS는 확장 시점 보류(잔여 리스크 기록됨).
- **NFR-6 품질**: 핵심 도메인(정원/선착순·출석 인증·집계·인증) 테스트 80% 목표, 머지 게이트 린트+테스트 그린.
- **NFR-7 API**: REST + springdoc-openapi 문서화, API 경계 DTO 사용(Entity 직접 노출 금지).

## 데이터·개인정보 (Data & Privacy)

- 수집 PII: 이메일·성명·닉네임(최소 수집). 사번 등 미수집.
- 저장 데이터: 계정, 코호트(정원·회차·기간), 참여/대기, 회차 출석·증빙 파일, 공지, 최종 보고서, 수료/정산 상태, 지표 집계.

## 가정 & 잔여 리스크 (Assumptions & Risks)

- (가정) 수료 기준(멘티, 출석 80%)과 정산 기준(멘토, 전 회차 인증+보고서)은 서로 다른 기준으로 취급.
- (가정) 관리자와 운영 담당자는 단일 역할.
- (리스크) 파일 업로드 보안 검증 부재(파일럿 보류) — 확장 전 검증 계층 추가 필요.
- (리스크) FE/BE 분리 저장소의 API 계약 동기화 준수 모니터링 필요.
